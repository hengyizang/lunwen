# G1 · 多机器人相互观测与报文时延

2026-11-21，本批追查 R5 的一个缺口：能否用公开记录区分机器人什么时候看见同伴、报文什么时候到达，以及控制器何时获得新的状态信息。实物地面机器人和固定网络台架分别提供了前两类记录。两个独立实验没有共同的机器人、报文编号或时钟，不能通过拼接重建一次闭环任务的信息年龄（AoI）。

## 引文与全文核验

从 MR.CLAM 数据论文和另一篇测距协同定位论文追查引文，并定向检索真实机器人通信计时研究。保留 17 条书目，按 DOI、arXiv 版本及作者题名与历史目录核对，10 条此前未收录。7 篇已核对全文，其中 4 篇是新书目。另有 1 篇核到出版商摘要。15 条引用关系记录了方向和核验来源。相同实测序列上的多次算法回放不能计作独立采集。[书目及逐篇证据等级](r5-literature.csv) · [引文关系](r5-citation-edges.csv) · [检索与排重日志](r5-literature-search.json)

- 一项四机器人实验用同一监听端给各机报文的到达时刻打戳。第一组配对试验中，各机器人“距上次收到更新的时间”之和的峰值从 15.8 秒降至 10.5 秒。这个结果支持比较接收端的更新间隔，单向传输时延还需要可对齐的发送时刻。原文 §4.9、图 20–22 和表 7–8 给出实验条件。[论文](https://doi.org/10.3390/s26154778)
- 另一项研究每种机群规模各运行 1,200 秒，每次有逾 13,400 次确认更新。观察端和服务器时钟未同步，表 3 采用应用层往返时延的一半估算上行时延，依赖上下行路径近似对称的假设。同一场运行内的大量报文不能增加独立实验次数。[论文](https://doi.org/10.3390/electronics15194555)
