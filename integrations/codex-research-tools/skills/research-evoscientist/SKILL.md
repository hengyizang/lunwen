# EvoScientist learning methods for Codex

Use project evidence to improve the next action without silently changing scientific rules. The independent EvoScientist CLI/TUI/WebUI and agents are separate software; this entry does not launch them.

## From observation to reusable procedure

1. Inspect the actual failed run, review finding or decision and current source files. Record scope, run/issue identifier, file hashes, observed symptom, relevant conditions and attempted remedy. Distinguish observation from a proposed explanation.
2. Check existing progress, issues and attempts before repeating work. Reuse a lesson only when source, context and dependencies still apply. It may suggest a test; it cannot establish a scientific conclusion or approval.
3. Relate evidence explicitly: `complements` adds compatible information, `contradicts` preserves unresolved conflict, directional `supersedes` identifies the old observation and new evidence replacing its applicability. Retain originals and explain scope; do not erase contrary or negative records.
4. If a procedure demonstrates reuse value propose a narrow change with trigger, steps, evidence, limits, dependencies and validation plan. Label it pending. Record actual acceptance and verification before adopting it; never self-promote a model suggestion into a requirement.
5. Continue the original task from the most useful permitted next step. Report changed evidence, remaining uncertainty and whether another test is needed.

Use existing project records rather than a second memory database. Do not write Codex global memory, profile or installed skills as a scientific-learning side effect; those changes need the user's direct request.
