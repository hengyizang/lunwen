# Concrete research task entry points

Use docs/RESEARCH-TASK-SCENARIOS.md with the existing stage writer, deterministic
cloud controller and independent audits. Do not switch models, add a planner
call, enable paid services or change the approved research scope for these tasks.
Output pending tasks rather than filling missing material with plausible facts.

## Public data and row provenance

For the actual topic, source, time window and variable dictionary, prepare a
field plan and authorized acquisition manifest first. An access failure is a
failure, not a collected record. Owner-supplied cloud files need the same source,
rights and exact-byte checks. Request data_row_prepare for current original row
identities; populate the declaration for data_row_provenance without deleting
duplicates. Preserve every original row and uncertain field. Record source URL,
actual published/collected dates separately, original row/page/table location,
missingness reason and conflicts. Unknown publication date stays null. A source
URL, dataset-row location or checksum never establishes semantic correctness.

## Recover a remembered claim

Write program/source-trace.json with the remembered statement, source leads and
current candidate library IDs. Request literature_source_trace. Bind executed
searches and identity evidence to actual receipts; locate original sentences
and their premises and applicable scope. Distinguish author statement, indirect
citation and reader interpretation. Retain excluded candidates with reasons.
Never call the earliest located result the historically original source without
the actual citation-chain evidence and scientific review.

## Criterion-level screening quality

Request literature_screening_advice using the existing screening/protocol hash
and exact criterion texts. For each study, stage and criterion provide a bounded
include/exclude/review suggestion, exact original evidence and missing material.
Mark suspected duplicate reports as leads; do not merge studies on title alone.
No accessible full text means a pending review, not final exclusion. Never edit
formal screening decisions or invent human reviewers; existing independent
review, adjudication, risk-of-bias tool and gate authority remain mandatory.

## Actual data analysis

Use the current data dictionary/contracts, empirical design and cloud runner.
State missingness/outlier handling before analysis, compare methods against the
estimand, independent unit and assumptions, and specify actual diagnostic runs.
Preserve original data, all registered specifications and adverse/failed results.
Code, proposed test and generated reporting template are not executed analyses.
Write result-bearing text only from current sealed outputs. Independently check
key computations against the same pinned data and declared numerical tolerance.
Unsupported method variants require an appropriate reviewed adapter, not a
silent approximation or significance-driven change.

## Question-centered synthesis

Reuse the complete current literature matrix. For each synthesis judgment bind
supporting and contrary cells, explain disagreement along construct, population,
data, method, identification, measurement, statistics, protocol or scope axes,
and preserve the inference boundary. Assess design, bias, comparability and
uncertainty individually, with located rationale or explicit unknown status.
Request literature_synthesis for a three-level argument outline. Evidence
strength is not a vote by papers, citations or model confidence. Use the plan
for related work, a question dossier or study protocol; it does not create an
extra narrative-review paper for the six-paper doctoral portfolio.

## Relations before diagrams

Keep the existing typed diagram IR and figure_story brief. List each node,
relation kind, source location, planned/method/observed phase and open question.
Never infer causal paths from workflow ordering or convert associations into
effects. Request diagram_mermaid only with the exact current IR and story_ref.
The code is editable; stage labels and relationship kinds remain visible.
Inspect the rendered diagram and follow existing figure approval before use.

## Bilingual, tiered and auditable search

Prepare a concept table with Chinese/English terms, aliases, disciplinary senses
and located terminology evidence when available. Broad/medium/strict concept
sets must be nested within the same doctoral question and have reasons. Request
literature_search_strategy for platform-specific drafts and trial logs. Manually
validate WoS/CNKI syntax and use authorized exports rather than bypassing access.
Exclude only declared scope categories, never adverse evidence. Keep platform
total, actually retrieved, deduplicated and screened counts separate; unknown
totals stay null. Adopt a reviewed plan in the existing writer flow, preserving
versions, query receipts, failures and reasons for adjustments. A generated
query is not an executed search or proof of exhaustive coverage.
