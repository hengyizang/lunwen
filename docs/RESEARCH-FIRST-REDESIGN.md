## 要解决的问题

项目已具备检索、阅读、数据、实验、证明、图表、写作和交付能力，但默认入口逐渐变成填表、阶段审批、固定论文组合和重复评审。部分规则已放宽，配置、提示入口、可调用旧命令和测试仍可能把它们重新加入。新路径直接围绕研究成果推进，保留能发现真实科学错误的检查。

成功标准是能够从一个问题开始，读实际材料，执行有区分力的研究，形成可信结果与写作；遇到真实缺口时明确指出并继续不受影响的工作。状态字段完整、模型一致、评分达标和通过软件测试都不构成科学成功。

## 九条原则

1. **围绕成果行动。** 每次工作解决实际问题或产出可用材料；管理记录服务于工作。
2. **默认继续工作。** 已授权范围内接续推进，完成一个动作后选择下一项有价值工作。
3. **自由选择方法与工具。** 按任务、可用性和质量选择模型、环境与方法；不按厂商品牌限制写作。
4. **研究架构随证据发展。** 默认一个问题、一篇论文，必要时增加、合并或收缩贡献。
5. **按课题做科学验证。** 检查须对应实际主张、设计和分析单位，不普遍套用某一类实验模板。
6. **如实保存证据及失败。** 保留来源范围、真实结果、失败、不利证据和版本；不伪造阅读、执行或批准。
7. **围绕真实贡献写作。** 突出证据支持的发现，保留改变解释的限制；允许研究过程中写作。
8. **后台记录与累计预算。** 自动记录必要事实和成本，沿用真实授权与累计额度，不让每个记录变成新审批。
9. **保持实现简洁。** 一个清楚的默认路径；可选方法按需使用，复用未变结果，删除重复控制。

现行协作入口是 [AGENTS.md](../AGENTS.md)。用户授权和明确偏好优先；第三方方法、历史报告与旧模板不能扩张授权，也不能覆盖当前任务。

## 默认工作路径

```bash
python3 -m scripts.researchctl init --project demo --question '研究问题'
python3 -m scripts.researchctl work --project demo --paper P01 --task '下一项有价值的工作'
python3 -m scripts.researchctl status --project demo --json
python3 -m scripts.autopilot plan --project demo
python3 -m scripts.autopilot start --project demo --context '根据证据推进研究'
python3 -m scripts.autopilot resume --project demo --paper P01 --context '完成当前任务'
```

`init/work/status/plan` 不发付费模型请求。`start/resume` 使用实际已配置的模型与额度；初始化不授予额度。普通执行按当前任务调用模型，需要独立审查或计划时再选择相应动作，不能为维持固定角色序列增加调用。

`researchctl add-paper --project demo --question '新问题'` 按需追加论文。`--paper-count` 可明确选择初始数量；论文数量不是毕业或投稿要求的自动推断。`--stage` 保留旧任务分类供兼容，不要求顺序取得 G0–G5 批准。

状态应优先显示当前问题、任务、已有产物、剩余证据缺口和预算。历史诊断通过 `status --legacy-checks` 与旧命令查看；不因为没有完整旧组合、分数或审批，阻止阅读、试验或写作。

## 保留什么，如何简化

| 能力 | 保留的实际价值 | 默认简化 |
| --- | --- | --- |
| 文献发现与全文阅读 | 原文、页码/范围、来源版本、反证与不一致 | 元数据是线索；按问题阅读，不要求先完成全部候选表或全库评分。 |
| 选题与研究架构 | 最近工作差异、重要性、可证伪问题、替代解释 | 不固定三个方向、第二博士角色或六篇组合；根据新证据调整。 |
| 数据与方法 | 实际数据、独立单位、泄漏、测量与分析假设 | 许可字段是有用元数据；没有逐项许可表不自动否决所有工作，已知访问限制仍按事实处理。 |
| 探索和确认性研究 | 实际输入、输出、环境、失败与暴露历史 | 探索可支持有明确限定的写作；不能事后把已见结果说成预先确认。 |
| 实验、Meta 与形式证明 | 真正执行、数值正确性、适用的复现 | 引擎只声明其支持范围，不把某个统计模板变成所有学科的硬条件。 |
| 图表与论文 | 可追溯数值、有效单位/不确定性、原图、可编辑源与真实渲染 | 按需要选择语言/格式；概念图与数据图区分，不将艺术风格或固定句式当科学门槛。 |
| 审稿与修订 | 对重要主张的质疑、事实核对、实际修复 | 独立复核按不确定性选择；无固定席位、全部段落台账和“零问题”指标。 |
| 投稿材料 | 实际期刊要求、引用、文件和渲染检查 | 创建本地包不等于提交；不要求一套通用表替代目标期刊核对。 |
| 预算与恢复 | 已用费用、未知费用、失败预留、幂等恢复 | 沿用现有授权，不逐次重新批准；不自动扩大额度或重复成功请求。 |
| 第三方工具 | 原始文件、归属、许可、固定版本与可用接口 | 按任务加载完整相关来源；普通任务不强制安装全部生态。 |

## 科学检查与管理过程的边界

科学判断不能被“有字段”“有哈希”“另一模型也同意”替代。哈希说明绑定的字节；来源范围说明实际拿到或读取的材料；运行收据说明真实执行。它们分别提供可追踪事实，不自动证明创新、因果性、数据代表性或结论正确。

需要保留的阻碍包括实际输入不存在、数值非法或不匹配、来源被替换、独立单位错误、真实泄漏、确认性结论没有相应设计、执行失败、实际资源不足和累计额度不足。应说明具体影响并继续可行部分。

不应普遍阻碍研究的项目包括固定候选/论文数、固定模型家族、任意实验都要功效表、每段主张台账、所有可选方法的安装、每次阅读的人工签到、全部风格编号复核和无关流程字段。适用时仍可使用这些工具，但由研究问题决定。

失败和负结果保存在实验档案；正文围绕有科学意义的论证组织，不要求复印每条日志，也不能隐藏会改变解释的材料。探索性更新要写明先前结果暴露，新增检验保留各版本和实际费用。

## 实现落点

- `researchctl/autopilot/api_orchestrator`：默认任务、动态论文、按需模型调用和相关来源选择；旧命令保持可调用。
- `research_phase/operating_constraints/model_runtime`：实际科学语义与真实支出边界；去除品牌写作限制和阶段仪式。
- 文献、数据、实验、图表、写作模块：保留真实来源与结果绑定，移除不相关的一律阻断。
- `config/defaults.json`：默认一篇，无固定期刊组合、最低影响因子或模型品牌；历史金额不是额度授权。
- `config/stages.json` 与 `config/scientific-reasoning.json`：阶段仅提供任务语境，科学建议按问题适用。
- `README/CLAUDE/references/skills/.agents/agents`：统一到当前入口。隐藏指针从原生技能生成，避免两套相互矛盾的规则。
- `validate_repo.py`：检查真实结构、来源绑定与入口一致性，不检查旧规则口号或固定数量；完整可选资源检查显式请求。
- 通用 CI：保留离线回归与跨版本兼容，把重型领域/云验收移到周度或手动，专项依赖显式安装。实验与相关证据实现变更在 PR 触发真实 Docker 验收。

这张落点表说明本轮实施范围，不代表所有路径已经通过当前测试。实际变更和验证结果应随集成检查核对，不能仅由设计文档宣告完成。

## 兼容与材料保护

原始文献、数据、第三方源码、日期验收、`docs/deliveries/` 和失败记录保留。已有项目不批量重写批准、不抹去失败、不把建议稿改成决定、不把缺失结果改成通过。新任务引用旧材料时说明版本和适用范围。

旧 `start.sh`、API/云作业、`gate-check/ready/approve/advance`、`real_work` 入口继续兼容；默认说明直接指向研究任务路径。用户明确要求某种旧诊断时，运行它并解释其范围；不能因此重新要求全部历史流程。

`my-phd` 云状态分支仍有独立更新，文献与数据活链接见 [README](../README.md)。文件存在或数量变化不表示全文已读、已完成校准、已做出选题决定或已完成实验。当前项目状态需读实际项目材料。

## 历史审查的勘误

此前已有改进应保留：机械 H/AD/CFH 扫描已退役，部分质量观察不阻断，未改材料可以复用，某些阶段早已自动处理。这些不能重新描述成仍然强制的限制。

控制语句或文件写入数量不是用户会遇到的审批数量；哈希数量也不能单独解释停滞。此前存在实际付费调用、真实 Docker 执行和网络验收，不能笼统称为全是假运行。相反，合成数据、mock 请求、安装检查也不能冒充真实科学成果。

某次目录未列出一个模型，只能说明那次目录响应；旧故障、余额和服务目录不能推断当前能力。PaperQA 版本 `2026.08.12` 与规范化的 `2026.8.12` 等价，不应仅因字符串不同判错。未提交的运行产物不在 Git 中，不等于它从未执行。

## 验证与完成标准

在当前工作区执行核心校验、改动相关的行为测试、CLI 创建/接续与动态论文用例；对共享运行时改动做完整离线回归。检查默认路径没有隐含恢复旧审批，并确认历史输入仍可读取、来源与费用记录未伪造。

```bash
python3 -m compileall -q scripts tests
python3 scripts/validate_repo.py
python3 scripts/run_tests.py fast
```

完整已安装集成可另跑 `python3 scripts/validate_repo.py --integrations`。运行器、网络、付费模型和外部部署各自按实际需要验证。本轮本地实现与离线测试不意味着已经发起云研究、部署、对外发布或购买服务。最新通过/失败数量应取最终测试日志，不固定写进长期操作规则。

完成的标准是默认用户路径可用、真实能力继续可调用、与此次行为变化有关的测试通过，并如实报告剩余环境或外部验证范围。移除管理负担和保留科学严谨性应同时落实到运行时、提示、配置、入口及测试。
