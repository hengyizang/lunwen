- **职责**：检测返修前后稿件**未授权的数值 / 引用 / 主张强度 / 公式 / 科学上下文漂移**。CLI 经 `paper_audit_cli` 输出 `reviews/revision-integrity.json`。支持 `.tex`（含 includes）与 `.docx`（OOXML）。

- **输入输出**：base = `reviews/revision-base/<canonical.name>` 或 legacy `reviews/revision-base<suffix>`，current = `ref_verify_adapter.canonical_manuscript`；授权文件 `reviews/revision-authorizations.json`（schema 1.0 人工：`approved_by/approved_at`；schema 1.1 `automated_change_record`）；输出报告含 `base/current{path,sha256}`、`authorization`、`changes{*_changes}`、`character_findings`、`revision_ledger`。

- **依赖**：`research_artifacts`、`citation_audit`、`manuscript_language`、`ref_verify_adapter`、`output_provenance`、`revision_ledger`；可选 `zipfile`/`xml.etree`（标准库）。
- **边界限制**：DOCX OOXML 包 50MB、`document.xml` 10MiB 上限；`record_automated_changes` 会归档旧人工授权到 `state/revision-control-history/`；反复显式声明 `semantic_equivalence_proven=False`、`human_scientific_review_required=False`、`independent_scientific_review_required=True`——机械对应**不等于**语义等价。
- **标注**：【硬编码】`NUMBER_RE/SIGNAL_RE/PROTECTED/FILLER/SI_UNITS` 词表、`W` 命名空间；【网络/付费 API】**无**；【名实不符】文件名「integrity」实际做的是**漂移检测 + 授权核对**，不证明完整性/等价（代码已自述）；【风险】`record_automated_changes` 自动写入 `decision_kind="automated_change_record"` 且 `human_review=False`，虽不改科学结论，但把「变化已记录」自动化，需依赖独立 critic 兜底。

### 4. `revision_ledger.py`（384 行）

- **职责**：**哈希绑定、完整的科学修订台账**。docstring 强调：TeX 源句与 Word 段是机械源单元，非语言学断言；作者提供 reason / claim ID / 精确证据引文；通过的台账只证明**对应与覆盖，绝不证明等价**。「no semantic verdict or model calls」。
- **对外能力**：`source_snapshot`、`change_manifest`、`needs_ledger`、`_claims`、`_evidence`、`audit`、`refresh`、`validate_saved_report`；大量内部：`_sentences`、`_facts`、`_unit`、`_xml`、`_delta`、`_aggregate`、`_paper`、`_baseline`。
- **输入输出**：输入 `reviews/revision-ledger.json`（作者草稿）、canonical 稿件与其 `revision-base`、`claims/claim-evidence.csv`（经 `paper_execution.artifact_path` 定位）、独立证据文本源；输出 `reviews/revision-ledger-report.json`（`save_report`）。
- **关键机制**：`source_snapshot` 把 TeX includes 切成「源句」、DOCX 切成段落 + 非段落结构 + 每个 OOXML package part，每单元带 `protected_facts`（`numeric/citation/qualifier/unit/formula/contextual`）与 `source_sha256`；`change_manifest` 用 `SequenceMatcher(autojunk=False)` 对 `old/new` 单元做 `replace/delete/insert` 差分，按 `json_digest` 生成 `change_id`，自动分类 `scientific`（含受保护事实变化）/`editorial`，`claim_ids/evidence/reason` 留空待作者填；`audit` 用 `Counter` 校验每个确定性 change 恰被覆盖一次、字段与重算完全一致、`reason` 必填、`editorial` 不得覆盖 `scientific`、`scientific` 变更必须带已注册 claim ID 与独立证据锚；`_evidence` 要求文本后缀白名单、精确引文 `count==1`、hash/start/end 一致，且证据源不得是台账/稿件自身（`forbidden`）。
- **依赖**：`citation_audit`、`ref_verify_adapter`、`research_artifacts`、`revision_integrity`（`NUMBER/PROTECTED/SI_UNITS/signatures/WordSource/revision_authorization`）、`paper_execution`；标准库 `csv/zipfile/difflib/ElementTree`。
- **边界限制**：canonical 稿件仅 `.tex`/`.docx`；DOCX 拒绝未解决的 `w:ins/w:del/moveFrom/moveTo` 修订；报告显式 `semantic_equivalence_proven=False`、`evidence_entailment_verified=False`、`human_scientific_review_required=True`；`alignment` 注明「exact equal units; positional pairing; no semantic correspondence claim」。
- **标注**：【硬编码】FORMULA/CITE 正则、SI_UNITS、`W/M/R` 命名空间；【网络/付费 API】**无**；【风险】`SequenceMatcher` 位置配对是机械近似，注释已声明「not semantic equivalence」；DOCX 结构对比用 `copy.deepcopy` + 删除段落后的骨架哈希，属启发式。

### 5. `revision_render.py`（150 行）

- **职责**：从**已渲染的稿件 PDF** 生成哈希绑定的页/行索引，供 PDF 行级定位使用。docstring：「reads PDF bytes; never renders, calls a model or invents pages」。
- **对外能力**：`source_hashes`、`pdf_pages`、`validate_render_receipt`、`build_render_manifest`、`validate_render_manifest`。无 CLI。
- **输入输出**：写 `reviews/revision-render.json`（`schema 1.0/status pass/generated_by/manuscript_sha256/source_hashes/pdf{path,sha256}/page_count/pages/renderer{name,version}/line_numbering`）；读 cloud 渲染回执；输出 `printed_line_numbers_verified=False`、`visual_review_required=True`。
- **关键机制**：`pdf_pages` 依赖 **PyMuPDF(fitz)**，`get_text("dict", sort=True)` 按阅读序抽取非空文本行；`validate_render_receipt` 校验回执 `mode=="cloud"` + `receipt_id`、renderer 白名单且 `implementation_sha256` 与本地 `cloud_runtime.py`/`word_render.py` 当前哈希一致、inputs 绑定每个 canonical 源、outputs 绑定实际 PDF、`current_origin` 要求 `tracked/family=other/provider/role=render-receipt`；`validate_render_manifest` 重算 PDF 文本与 pages 防陈旧。
- **依赖**：可选 `fitz`（PyMuPDF，缺失即 `ValueError`）、`citation_audit`、`ref_verify_adapter`、`research_artifacts`、`output_provenance`。
- **边界限制**：PDF ≤100MB、1–1000 页、拒绝加密/空；`build_render_manifest` 强制 `rendering_receipt` 非空；行号是「抽取的阅读序文本行」，**不是**印刷行号，也不等于 Word 分页。
- **标注**：【硬编码】`renderers={"cloud_runtime":("cloud_runtime.py","cloud-tex-renderer"),"word_render":("word_render.py","cloud-word-renderer")}`；【网络/付费 API】**无**；【文档 vs 实现】README 宣称「实际渲染视觉检查」——本模块只做 PDF 文本行索引，`visual_review_required=True` 把视觉复核留给人/外部；【风险】`implementation_sha256` 绑定的是**仓库内脚本文件哈希**而非渲染器二进制/版本，若脚本被改需重算回执（设计如此）。

#### 4.3 安全与数据完整性风险

- **高 blast radius 持久状态改写**：`reviewer_rounds.start_revision`、`scientific_scope.seal_approval/apply_amendment`、`supplemental_experiments.approve/confirm/retire`、`study_routes.prepare_runtime`（回填 plan）——均有 cloud 门槛 + 归档/回执/CAS，但改动 `state/run.json`、approved_gates、paper_statuses，需完整人工授权链。
- **身份/授权多为字符串自报**：`actor`、`confirmed_by`、`imported_by`、`authorized_by`、`approved_by` 无密码学签名；`scientific_scope.seal_approval` 只核对 `actor` 字符串。
- **「机械对应 ≠ 语义验证」**：`statistical_reporting`/`study_routes.reporting_audit` 用 `display_value` 正则比对数值、`revision_trace` 用 `excerpt in text` 子串、`revision_ledger` 用 `SequenceMatcher` 位置配对、`validate_repo` 用文件存在/字符串包含、`watermark_cleanup` 用 DISCLOSURE 正则保护、`skill_catalog.lint_skill` 用正则——代码普遍以 `*_verified=False` 自述边界，依赖独立 critic 与 G1/G2 人工闸门兜底；若上层把「软件检查通过」误当「科学完成」即违背 AGENTS 规则 5。
- **第三方/SDK 强耦合**：`third_party_runtime.cmd_run` 的 `argv` 来自 `REMAINDER`，可执行文件/参数不受仓库内路径限制（靠 tier 授权把关）；`tooluniverse_worker` 的 `patch` 依赖「SDK 内部用 `requests.get`」的实现假设；硬编码哈希/版本使升级即失效。
- **规则张力**：`web_research` 的 `paper_limit_cny=60` 与 AGENTS 规则 23「Do not add per-paper/per-request sublimits」字面有张力（README「不再设单篇额度」）；`settle` 前失败保留 reservation（符合「每次尝试都计数」但需人工对账）。`venue_candidates` 的 `date.today()` 判定 jcr_year 跨年失效。
- **正向防护较完整**：ZIP/归档普遍防 symlink / 路径逃逸 / 密钥类 / 隐藏文件 / 解压炸弹（`submission_package.safe_file`、`venue_compliance.normalize_member`、`watermark_cleanup._docx`、`reviewer_rounds._snapshot`、`revision_integrity.word_package`）；`reviewer_rounds.prompt_feedback` 把审稿文本当不可信数据；`statistical_watermarks._worker` `except Exception: return 2` 防密钥/tokenizer 内容泄漏；`web_research` 用 `NoRedirect`；`tooluniverse_worker` `allow_redirects=False`。
