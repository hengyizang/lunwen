## 一句话结论

**这是一套把「不许造假」做到极致的博士科研流程控制平面，不是一套已经写出论文的系统。** 工程脚手架（证据链、哈希、预算、闸门、回归测试）极其完备，但真实科研产出为零，项目仍停在 G1 入口，`G1/G2 从未人工批准`，六篇论文全是空模板。系统自己在验收记录里写明：`Implementation is software capability, not research completion`。

## 一、项目定位

面向个人博士研究者的**可审计科研工作流**：Python 确定性控制层（`scripts/`）+ Claude/OpenAI API（规划/写作/独立批评）+ GitHub Actions（云端执行），把「宽领域探索 → 博士选题 → 六篇独立论文 → 投稿准备」接到同一套证据与费用记录上。

核心信条（`AGENTS.md` 25 条规则）：不编造引用/数据/实验/结果/审稿/期刊指标；每条主张在 `claim-evidence` 矩阵里绑定证据才算数；G1 博士选题、G2 逐篇选题必须真人决定；Claude 只做只读规划与独立审计，OpenAI 写持久产物；结果图必须由本地脚本从已登记数据渲染；**绝不自动投稿**；工程验收不等于科学有效、博士资格或期刊录用。

## 三、能力全景（12 个域）

1. **流程状态机与 G0–G5 闸门** — `researchctl.py`（720 行）聚合七阶段；G1/G2 人工 `approve`（G2 逐篇投票），其它阶段由 `ready` 产生机器决定后 `advance`；`ready/approve/advance` 三段式 artifact-hash 绑定；终点 `submission_ready`，无自动投稿代码。
2. **模型编排与角色隔离** — `api_orchestrator.run_cycle`：planner（Claude 只读）→ writer（非 Claude 写持久产物）→ 独立 critic → 仅在有问题时触发修复/复审；G5 用三个不同模型家族的互盲来源视图，冻结意见、保留分歧；`validate_roles` / `reject_long_source_copy` / `record_writer_provenance` / `safe_target` 把角色隔离变成 Python 硬约束。`ai_providers.py`（1194 行）定义 17 provider / 12 条生产路由、模型 ID 精确回显校验、SSE 严格解析、usage 归一化、响应脱敏与哈希留痕。
3. **累计费用控制** — 默认项目总额 300 元（当前配置 500），一次预留一次 POST，保守成本上界，每次尝试（含失败/超时）都计费；`model_spend` 跨进程锁 CNY 账本，`billing_quotes` / `relay_billing` / `relay_guard` 做报价、结算、对账与共享凭据守卫；无单篇/单次子限额，不自动提额。
4. **文献情报与证据链** — 8+ 公开/付费源检索（arXiv、S2、DBLP、PubMed、Crossref、OpenAlex、Unpaywall、WoS/Scopus 导出）；原始响应先落盘再双 SHA-256 收据 + 不可变 ledger；BM25 持久全文索引 + CPU ONNX 稠密向量/交叉编码重排；26 字段阅读卡、逐字锚点校验、句子/页导航、20 轴实验比较矩阵、PDF 抽取与标注（OCR 不替代原文）；Zotero Web/Local、Obsidian 接入；`citation_audit.py`（1011 行）做引用身份核验与逐主张全文证据三态 + 15% 抽检。
5. **数据供应链** — 元数据发现只产出 `leads`（不授予许可、不作纳入决定）；SSRF 防护的 HTTPS 下载、content-addressed 缓存；变量字典、清洗、面板/时间检查、经济数据 vintage、行级溯源；G3 冻结计划内的数据契约逐文件哈希；许可/研究用途为可选元数据，缺证据则停。
6. **实验执行与结果证据** — `experiment_runner.py`（1230 行）是唯一执行入口：复核 G3 冻结的 plan/budget/preregistration 哈希后，在 `--network=none --read-only` 容器内跑已批准命令；无 shell 调用、可执行文件白名单、路径限制、超时、租约防并发；每次尝试（含失败、负结果）全量归档到 `experiments/archive/Pxx/`。`experiment_evidence.py` 串起预注册假设/证伪条件、executor receipt、scipy 重算、Holm 校正与 claim 覆盖；明确不确立因果或新颖性。

## 五、代码里真实存在的外部调用点

绝大多数模块是确定性本地逻辑。真实出口很少，且被严格约束：

- 付费模型：`review_panel.run()` 的 3 次三家族互盲调用、`task_router --execute`、`literature_comparison` / `paperqa` / `paper_reader` / `calibration` 的 `model_runtime.call`、`web_research` 的 Tavily 计费 POST；`ai_providers` 是端点本体。
- 公网 GET：`research_support.fetch_sources()`（≤10 次）、`tooluniverse_worker`、`free_jev_probe`（OpenRouter 零花费探针）、文献/经济元数据 API、eLife/Crossref 公开锚点。
- 云与系统：`cloud_job` 的 `gh api`、`study_environment` / `word_render` 的 docker/apt/pip、`literature_pdf.provision` 的 `sudo apt-get`、`skill_catalog` / `third_party_runtime` 的 git/subprocess。

其余「验收」「校准」「一致性」几乎都是合成夹具，代码里普遍标 `paid_calls=0`、`advisory_only`、`*_verified=False`、`not_scientific_evidence`。

## 七、安全与工程风险

1. **云闸门可伪造**：仅凭环境变量 `GITHUB_ACTIONS` / `DR_OS_CLOUD_EXECUTOR` 判定。`acceptance_scope.py` 甚至展示用 `DR_OS_CLOUD_EXECUTOR=1` + `seal_approval` 生成「人工批准」记录的路径。
2. **人工授权边界**：`cloud_human_controls.execute` 未传 `owner_authorization` 时，会以 `verified=False` 的「本地声明」身份记录人工决定；`actor` / `approved_by` / `imported_by` 多为字符串自报、无签名，多处可改写 `state/run.json`。
3. **网络**：`network_safety` 校验时解析的 IP 与 urllib 实际连接不绑定（DNS rebinding / TOCTOU 窗口）；`literature_assets.resolve` 接受任意 HTTPS、无发布者域名白名单；`attest_human_files` 只改 provenance registry 不改文件字节。
4. **哈希覆盖**：`artifact_hash` 刻意排除 `state/`、`experiments/runs/`、`raw/` 等目录，形成潜在绕过面；本地哈希无签名，依赖 `output_provenance` 记录。凭据脱敏仅按变量名启发式匹配。
5. **许可**：`ars-review` / `ars-codex` 三份文档及自研目录内改编文件受 **CC BY-NC 4.0 非商业**约束，与付费 API、云端作业、投稿准备存在潜在冲突；历史快照另含 AGPL-3.0 与 custom noncommercial。
6. **未接线/锁死**：`upstreams.lock.json` 46 源、`research-automation-tools.json` 11 工具全部默认未启用，`standalone_runtime_deployed=false`，`third-party-runtime.json` 的 `tools: []` 且 guardrails 全 false；owner decision 明确「授权 ≠ 部署」。

## 八、测试覆盖的真实含义

195 个测试文件 / 44,534 行，对「证据链、来源哈希、累计预算、失败留痕、角色隔离、闸门、绝不自动投稿」形成极密的工程回归保护；大量断言主动写死 `scientific_completion_verified:False`、`gate_authority:False`、`NOT_CALIBRATED`。

**但**：所有真实付费 API、真实网络、真实 Docker 实验、真实人工 G1/G2 决定、真实独立 critic 都被 mock 或合成替身替代；真实 CPU 语义、水印 runtime、TeX 编译等 20+ 处 `@skipUnless` 实机用例默认不跑，普通 `unittest discover` 只跑纯合成逻辑；共享夹具 `sealed_run` / `seal_review` 会伪造「G3 批准 + 成功回执 + 独立审查通过 + 人工确认」供 20+ 文件复用。唯一真实数值例外是 R metafor golden 数值与 scipy t 区间。

**结论**：测试能证明「控制平面按规则运行」，不能证明「科研结果成立」。未发现测试直接违反 `AGENTS.md`。

## 十、设计权衡：防幻觉是否过度

**结论：是，明显过头，且已从「防止造假」异化成「证明自己没做事」。** 完整论证见 `01-防幻觉过度性评估.md`，此处只列关键数据。

| 指标 | 实测 |
|---|---|
| `raise` : 实际写入语句 | **4,730 : 688 = 6.88 : 1**（197/205 文件含 `raise`） |
| 防御型 : 产出型函数 | **272 : 173 = 1.57 : 1** |
| `verified=False` 类标记 | 345 次 / 107 文件；不同「未验证」键名 **226 种 / 748 次** |
| 哈希绑定 | 3,417 次 / 177 文件（**88%**） |
| 文件名即校验/审计类 | 52 / 205（25%） |
| 测试 mock 注入 | 461 处 / 108 文件（55%），18 处默认跳过 |
| 文档免责表述 | 76/83 篇 docs，共 354 处 |

四种真实代价：**① 信号稀释**——当所有字段都是 False，False 不再携带信息，226 种键名把「未开始/未通过/不作判断」揉成一团；**② 成本爆炸**——改一处要同步 Python、schema、夹具、文档四层，反而制造出预算 300 vs 500、费用 0 vs 3.889 元等新不一致；**③ 责任真空**——每处判断都推给「人工/实证」，但 G1/G2 真人决定从未发生，流程死锁在 G1；**④ 自相矛盾**——最强调不可伪造的系统，其「人工批准」却可由环境变量与合成夹具伪造，`artifact_hash` 还刻意排除 `state/`、`raw/`。

需要保留的是少数作用在「不可逆且外部可见」边界上的护栏（G1/G2 人工决定、不自动投稿、来源哈希、累计预算、角色隔离、外部调用前校验）；应收敛的是 226 种状态键、69 个 schema、354 处重复免责；应删除的是 `retired`/`not_assessed` 占位模块与重复的验收报告。判断标准很简单：**好的护栏应该让真实工作更容易完成，而不是更难**——若运行至今仍停在 G1、零论文、零实验，该审视的是护栏本身。
