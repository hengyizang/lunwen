# Bounded model comparison, 2026-10-20

This is a new owner-authorized allowance of at most CNY30, separate from the
closed relay-acceptance-20261019 allowance and every research project budget.
Execution is restricted to the authenticated owner dispatch in GitHub Actions.
No local experiments, paid model judges, generation retries, automatic route
promotion or scientific gate approvals are introduced.

## Coverage and order

The frozen plan in config/model-comparison-20261020.json covers 22 exact
provider/model combinations across the ten configured groups and seven baseline
models. The Gemini key's authenticated catalogs advertise gemini-4-argon-high;
the base alias gemini-4-argon is not substituted silently. This is an exact API
name correction, not proof of model weights or quality. Gemini low/medium remain
untested because the configured key does not advertise their exact IDs.

First, every route gets two shared screening tasks, one round at a time.
Successful baselines then receive focused tasks before alternative channels:
source conflict, leakage and fair design, paired statistics, English claim
precision, long-source reconciliation and a synthetic chart. Two additional
Sol/Luna effort settings are compared only within the same remaining allowance.
The long and visual tasks are skipped where the implemented transport lacks
that modality; unattempted configurations remain unknown.

A seventh open scientific-planning task asks each screening-qualified baseline
for a falsifiable mechanism, novelty against supplied nearest methods, fair
controls, ablations, paired statistics and a feasible cloud CPU plan. Its hard
resource limits must be accounted for in the proposed fit count and decision
rules. This is an internal synthetic proposal, never a completed experiment.
Its output requires semantic review and receives no automatic numerical score.
Closed factual questions have explicit deterministic rubrics; those rubrics
cannot assess overall doctoral originality or replace human blind evaluation.

## Spending and failure controls

The fixed cloud-state/model-comparison-20261020 branch stores an independent,
append-only attempt ledger. The authorization ID, plan and fixture hashes, exact
routes and call IDs are bound. A rerun does not reset the allowance or repeat an
attempt. Closed and stopped trials stay closed/stopped. Reservations count in
full until an independently attributable gateway debit is read.

Each fresh attempt reads the group's independent meter, calculates a conservative
reservation from the current exact price contract including cache writing, and
persists it with optimistic locking and readback before any generation request.
All calls are serial and share the production cloud concurrency group. A failed
response is still recorded and billed when the gateway provides an attributable
debit. Unknown charges stop all new paid work and retain their full reservation.
The explicit reconcile mode performs only free metadata reads and never reopens
or generates. The old allowance and production spending files are never written.

Actual observed debit, requested/reported model, requested effort, termination,
usage, duration, exact task hash and raw synthetic answer are preserved. Only
documented typed usage fields are saved. Credentials, gateway error bodies and
account details are excluded. Requested effort and echoed model labels are
traceability records, not independent attestations of real reasoning or weights.

## Dispatch and interpretation

The workflow defaults to metadata inspection. Generation requires mode execute
and authorization model-comparison-20261020-cny30. The entry point independently
checks owner, repository, cloud runner, workflow_dispatch event and exact branch.
The screening phase uses a conservative CNY18 ceiling, focused comparisons the
CNY30 cumulative ceiling, with at most 128 unique attempts. An expensive final
reservation may leave some allowance unused. Remaining tasks are reported.

Review small-sample results as local screening evidence: compare factual errors,
unsupported claims, constraint violations, latency and settled cost per accepted
test. A perfect short fixture does not prove broad equivalence, high-context
reliability or suitability for core scientific judgment. No trial score alone
updates production assignments or dynamic acceptance records.
